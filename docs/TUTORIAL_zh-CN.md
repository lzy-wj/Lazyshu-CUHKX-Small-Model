# Lazyshu 项目学习手册：从任务到最终系统

> 目的：不是让你背代码，而是让你能独立回答三个问题：**任务为什么难、系统为什么这样设计、每个模块解决了什么问题。**

## 0. 先记住这一句话

Lazyshu 是一个面向 **跨受试者多模态行为识别** 的小模型系统：先用 CNN/RNN/Transformer 从视觉、骨架和 IMU 中提取片段级证据，再用轻量残差、受保护 Adapter、结构解码和确定性路由处理人员与环境分布偏移；最终运行资产为 `84.09 MB`，主提交私榜 `91.176%`、排名第 4。

---

## 1. 项目到底在做什么

### 1.1 输入与输出

每个样本是一个日常行为片段，可能包含六类原始模态：

| 模态 | 它记录什么 | 主要价值 | 主要问题 |
|---|---|---|---|
| Depth Color | 带深度信息的彩色视频 | 人体、物体、空间关系 | 背景变化、遮挡 |
| Thermal | 热成像视频 | 光照鲁棒的人体轮廓 | 纹理少、细粒度物体弱 |
| IR | 红外视频 | 暗光下的动作与轮廓 | 对比度低、噪声 |
| Skeleton | 17 个三维关节序列 | 姿态和大幅动作 | 手部与物体信息不足 |
| IMU | 最多五个设备的惯性序列 | 局部肢体动态 | 佩戴方向、设备缺失、个体差异 |
| Radar | 雷达点或时间信息 | 运动与采集时间结构 | 点云域差异明显 |

输出是 `40` 个行为类别之一。训练集有 `3,036` 个带标签片段，公开 Testing 有 `405` 个无标签片段。

### 1.2 比赛约束

- 主体架构只能使用 CNN、RNN、Transformer。
- 所有运行时模型资产共同小于十进制 `100,000,000 bytes`。
- 检测器、主干、Adapter、小型学生网络都要计入预算。
- 核心评测是对 held-out user IDs 的泛化，而不是记住训练人员。

### 1.3 为什么不是“六个模态全部塞进一个 Transformer”

六种模态的数据形态不同：视频是二维空间随时间变化，骨架是关节点序列，IMU 是高频一维传感器序列，Radar 又有自己的采样与噪声结构。一个编码器强行处理所有原始输入，会同时面临输入维度不统一、时间尺度不一致和参数预算过大。

我们的原则是：

1. **模态内编码专门化**：视觉用时空 CNN，骨架用 temporal CNN，IMU 用 Conv1D + BiLSTM。
2. **模态间融合统一化**：把各编码器输出投影成同维 token，再由 masked Transformer 交互。
3. **结构信息与神经证据分离**：Radar 最终不进入基础神经主干，只在 V164 中提供时间分组候选。

## 2. 真正的瓶颈是什么

### 2.1 不是训练能力不足，而是条件分布偏移

有些模型训练准确率可接近 `99%`，但 held-out 人员上只有约 `23%–53%`。这说明模型能拟合训练集，却不能稳定跨越以下变化：

- 不同人的动作幅度、速度与习惯；
- 不同环境、背景、物体和摄像机位置；
- IMU 的佩戴方向和设备组合；
- 采集脚本、日期与轮次结构；
- 同一动作类别中的细粒度外观差异。

所以后期研究重点从“加参数”转成了“限制适配范围、识别监督可用性、提供安全回退”。

### 2.2 held-out user ID 不一定等于全新自然人

必须区分：

- **user ID**：数据集中的编号。
- **natural person**：现实中的同一个人。

同一自然人可能在不同环境下对应不同 user ID。于是评测样本存在两种情况：

1. **有同人源域监督**：同一个人在另一环境有带标签录像。
2. **无同人源域监督**：没有同一人的任何带标签来源。

V127 的关键不是根据置信度猜谁该用哪个模型，而是按这两种监督条件做确定性路由。

### 2.3 本地分数为什么会骗我们

本地双折来自训练集中的人员和采集结构。测试集即使类别相同，也可能具有不同的日期分布、轮次排列和人员关系。因此：

- V160 本地 `90.05%`，公榜只有 `0.84079`。
- V166 本地最高 `90.35%`，公榜只有 `0.88557`。
- 最终获奖主方案 V127 本地低于 V166，但公榜 `0.92039`、私榜 `0.91176`。

这证明模型选择必须同时看跨用户验证、线上证据、规则复杂度和可复现性。

## 3. 验证协议：所有研究的地基

### 3.1 为什么不能随机按 clip 切分

如果同一用户、同一环境或相邻采集轮次同时出现在训练和验证中，模型可能记住人的外观、背景和采集脚本，得到虚高分数。我们采用 user-isolated folds：

- Fold 0：用户 `3/8/18/23`，`652` 个片段。
- Fold 1：用户 `5/7/17/22`，`705` 个片段。
- 合计：`1,357` 个开发验证片段。

### 3.2 两个 fold 应该怎样理解

早期主要在 Fold 0 选架构，再用 Fold 1 确认。但随着大量迭代，Fold 1 也多次参与了方案选择。因此最终报告诚实地把两者都称为 **development validation**，不能把 Fold 1 包装成独立测试集。

### 3.3 full-data refit 为什么没有 held-out 分数

设计冻结后，部署 checkpoint 使用全部 `3,036` 个训练片段重训。它没有留下独立 held-out 用户，所以表格中的本地验证分数来自排除对应验证用户的模型，而不是全量重训 checkpoint 本身。

### 3.4 晋级原则

一个候选通常需要满足：

- Fold 0 有明确改善；
- Fold 1 不退化或同样改善；
- 逐用户结果没有严重牺牲；
- 模型资产仍在 100 MB 内；
- 变化能由单变量或清晰机制解释；
- 最终重新推理能够复现。

## 4. 数据预处理

### 4.1 动态数据审计

系统先建立 clip 索引，再检查：用户、日期、类别、可用模态、帧数、设备数、数值有限性、CSV 顺序和文件哈希。早期发现 `79` 个抽样图像不可解码：优先使用同模态邻近有效帧替代；若整条模态无有效帧，则关闭对应 mask。

### 4.2 人物裁剪

YOLO11n 只做人物检测，不做行为分类。系统对一个 clip 生成稳定的 union window，而不是让每帧框独立抖动。这样能：

- 去掉大量背景；
- 保留人体与手边物体；
- 让 Depth、Thermal、IR 的空间区域更一致。

### 4.3 时间采样

视觉统一采样 `32` 帧，但并不要求 Skeleton、IMU 与视频逐索引一一对应。每个分支先在自己的时间尺度编码，再在语义 token 层融合。这叫 **late fusion / representation-level fusion**，比强行原始帧同步更稳健。

### 4.4 IMU 世界坐标化

IMU 在设备局部坐标中记录加速度和角速度。相同动作只要佩戴方向不同，数值就会变化。我们利用四元数把信号旋转到世界坐标，降低朝向差异，再构成 `85` 维时序输入。

## 5. 基础网络：CNN、RNN 与 Transformer 如何分工

### 5.1 视觉：共享 R(2+1)D-34

R(2+1)D 把一个 3D 卷积分解成：

1. 二维空间卷积，学习人体、物体和局部纹理；
2. 一维时间卷积，学习运动变化。

Depth、Thermal 和 IR 共用一个视觉主干，减少部署体积并提升跨模态参数共享。最终视觉输入可理解为由三种视觉流构成的时空证据，而不是部署三个完整大模型。

### 5.2 Skeleton：temporal CNN

输入包含关节坐标、骨向量和速度。temporal CNN 擅长学习局部时间模式，例如抬手、弯腰、往返摆动。它比单纯统计均值更能保留动作过程，同时比大型图网络更符合容量预算。

### 5.3 IMU：Conv1D + BiLSTM

- Conv1D：提取短时震动、冲击和局部变化。
- BiLSTM：从前后两个方向汇总整个片段的时序关系。

LSTM 属于 RNN，完全符合架构限制。它适合不等长传感器序列，但不能单独解决跨用户佩戴习惯差异，所以需要世界坐标化、缺失设备 mask 和多模态融合。

### 5.4 融合：masked Transformer

每个编码器输出被投影到 `192` 维 token。两层、六头 Transformer 让各模态彼此注意，例如：

- 视觉看到手靠近嘴；
- Skeleton 看到肘部弯曲；
- IMU 看到腕部运动；
- 融合后更容易区分喝水、吃东西和吃药。

`masked` 表示缺失模态被 attention mask 排除，而不是把零值误认为真实观测。

### 5.5 为什么是“一模态一编码器，再统一融合”

更准确的说法是：

- 三个视觉模态共享一个同类型时空编码器；
- Skeleton 与 IMU 各自使用适合自身结构的编码器；
- 编码后的 token 由同一个 Transformer 融合。

这兼顾了模态专门化、跨模态交互和 100 MB 限制。

## 6. 训练与压缩

### 6.1 基础训练配方

- AdamW 优化器；
- warmup + cosine learning-rate schedule；
- BF16 autocast，优化器状态保留 FP32；
- MixUp `0.3`；
- label smoothing `0.03`；
- EMA `0.99`；
- clip-consistent horizontal flip；
- masked-modality distillation。

### 6.2 参数汤不是模型集成

五个 full-data fits 使用不同训练来源和训练轨迹。它们的参数按固定权重做加权平均：

`0.082416 / 0.079504 / 0.148508 / 0.089572 / 0.600000`

得到一个新的 checkpoint。推理时只运行这个融合后的主干，不是五个模型分别前向，所以称为 **parameter soup**，而不是 **forward ensemble**。

### 6.3 INT8 存储与 BF16 计算

- 主干权重以 INT8 保存，减少文件大小。
- 运行时解量化，并以 BF16 前向。
- 所以“INT8 模型”在这里主要指存储压缩，不代表全程 INT8 kernel，也不代表显存只占模型文件大小。

### 6.4 为什么不直接部署多个大专家

多个 R(2+1)D 或 Transformer 同时部署会超过 100 MB。我们的解决方案是：

1. 大教师只在训练阶段存在；
2. 把教师差异蒸馏成小型 logit residual、sequence Transformer 或 Adapter；
3. 推理端只保留一个共享主干和若干轻量增量。

## 7. 三类后期增强模块

### 7.1 Logit residual

`logit` 是 softmax 前的类别分数。V52 不重新编码原始视频，而是读取基础模型适配前后的类别证据，学习一个小残差修正。

直觉：主干已经知道“像哪几个动作”，小模块只学习在某个 domain 中怎样重新排序。

### 7.2 Round Transformer

单个 clip 不总能独立判断，但同一 acquisition round 中的片段具有顺序与重复关系。V57 用小型 Transformer 学习序列级修正，并成功复现复杂教师的全部本地与测试决策。

### 7.3 Visual Adapter

Adapter 是插在冻结主干内部的小型残差模块。我们的视觉 Adapter：

- 放在视觉 layer 4 前后；
- 使用零初始化，使初始函数严格等于原模型；
- 使用 GroupNorm，避免小目标域污染 BatchNorm 统计；
- 只训练少量参数，降低灾难性遗忘。

### 7.4 FiLM

FiLM 通过条件信息对中间特征做缩放和平移，可写为：

`y = gamma(condition) * x + beta(condition)`

V71 的 FiLM 修正只在开发定义的一个 domain 打开。要特别记住：**在最终选中的 V127/V164 输出路径中，它没有直接改变标签。** 有同人源的样本走 V114；无同人源时 V71 gate 关闭，输出精确等于 V57。V71 资产仍因冻结复现而保留并计入大小。

### 7.5 Paired-person adaptation

当目标 user ID 与某个有标签 source user ID 属于同一自然人时：

- base checkpoint 排除这两个 ID，避免泄漏；
- source 环境使用真实训练标签；
- target 环境只使用模型伪标签；
- 训练小型视觉 Adapter；
- 最终使用 `60%` paired-adapter evidence + `40%` protected source evidence。

这形成 V114。报告只把收益归因于完整的“paired adaptation + anchored fusion”，因为没有完成只改变标签来源的严格控制实验。

## 8. 结构解码在做什么

神经网络输出每个 clip 的 40 类概率。结构解码并不是另一个大模型，而是利用训练阶段冻结的采集结构，修正一组 clip 的联合预测。

### 8.1 acquisition round

根据时间间隔把相邻片段分成一次采集轮次。一个 round 可以看成一小段动作脚本。

### 8.2 repeat pooling

如果两个 round 在长度和模型概率上高度相似，就把对应位置的概率进行池化，利用重复采集降低单次噪声。

### 8.3 transition score

从训练标签统计动作转移倾向。例如某些动作更常按特定顺序出现。解码时把 clip 的神经 log probability 与 transition score 组合。

### 8.4 beam search

不能穷举整轮所有 `40^T` 个标签序列，因此每一步只保留若干得分最高的部分序列，这就是 beam search。

### 8.5 pair-aware assignment

当存在同人源域时，可以把目标 round 与 source 序列模板比较。只有加入编辑惩罚后模板路径仍优于自由解码，才采用模板约束。

### 8.6 结构规则为什么危险

结构规则可能学到“训练集怎样采集”，而不是“动作本身是什么”。V160/V166 的失败说明：即使两折都上涨、甚至每个 held-out 用户都不退化，也可能无法迁移到测试采集脚本。

因此 V164 把结构结果降级为 challenger，只在原神经 posterior 明确支持时才接受。

## 9. 最终执行顺序

最终代码不是简单的“V127 后再跑一次 decoder”，真实顺序如下：

1. 基础主干生成多模态 posterior。
2. 分别构造并解码三个候选：V24 incumbent、无配对序列 anchor、V114 paired adapter。
3. 若存在合法同人 source，V127 选择 decoded V114；否则选择 V71 代码路径中的 decoded V57 anchor。
4. 若 V24 incumbent 类别不在 matched-source 标签覆盖范围内，恢复 decoded V24。
5. 对日期为 `2025-05-31` 且 protected V127 与 decoded V24 不一致的样本执行冻结 rollback；在已发布 405 条测试中对应 4 行。
6. V164 额外用 Radar 时间戳形成结构 challenger。
7. 仅当 challenger 的原始多模态 posterior rank `<= 2`，且当前 primary 的 rank `>= 3` 时接受 challenger。
8. 输出 CSV，并检查行序、路径、空值、重复项和标签范围。

### 9.1 incumbent 与 challenger

- **incumbent**：当前可信、默认保留的预测。
- **challenger**：某个新模块提出的替代预测。
- **evidence gate**：只有新预测得到独立神经证据支持时才允许替换。

这是后期最重要的泛化思想：**新模块没有自动改标签的权力。**

## 10. 最终结果怎样解释

| 系统 | 本地开发 | Public | Private | 决策 |
|---|---:|---:|---:|---|
| V127 primary | 1205/1357，88.80% | 0.92039 | 0.91176 | 最终主提交，私榜第 4 |
| V164 radar hedge | 1213/1357，89.39% | 0.91044 | 0.90686 | 最终次提交 |
| V166 local best | 1226/1357，90.35% | 0.88557 | 未选 | 本地结构过拟合 |

V127 不是本地分数最高，却是最终最好，说明方案选择的目标应是未知分布泛化，而不是开发集极值。

## 11. 高频术语词典

| 术语 | 白话解释 | 本项目中的位置 |
|---|---|---|
| Modality | 一种数据来源 | Depth、Thermal、IR、Skeleton、IMU、Radar |
| Clip | 一个待分类的行为片段 | 每行 submission 对应一个 clip |
| Cross-subject | 训练和评测人员分离 | 两个 user-isolated folds |
| Domain | 具有共同人员/环境/监督条件的数据子群 | V52/V71/V104 的门控条件 |
| Domain shift | 训练与测试分布不同 | 全项目核心瓶颈 |
| Encoder | 把原始输入转成特征 | R(2+1)D、temporal CNN、BiLSTM |
| Fusion | 组合不同模态信息 | masked Transformer |
| Token | Transformer 接收的向量单元 | 各模态的 192 维表示 |
| Attention | 根据相关性动态聚合 token | 模态间交互、序列建模 |
| Mask | 告诉模型哪些模态无效 | 缺失模态不参与 attention |
| Posterior | 模型对各类别的概率分布 | V164 的证据门控依据 |
| Logit | softmax 前的类别分数 | V52 residual 的主要输入/输出 |
| Pseudo-label | 模型给无标签样本生成的标签 | V24/V89/Adapter 自训练 |
| Teacher | 提供软标签或目标行为的复杂系统 | 训练期多模型/结构系统 |
| Student | 学习复现教师的小模型 | V52、V57、V71 |
| Distillation | 把教师知识传给学生 | logit、round、masked distillation |
| Retention KL | 约束新模块不要偏离原模型太远 | residual 与 Adapter 训练 |
| Adapter | 冻结主干时训练的小增量模块 | V97–V114 |
| Residual | 在原输出上学习一个小修正 | V52、视觉 Adapter |
| FiLM | 条件缩放和平移特征 | V71 开发学生 |
| Parameter soup | 多个 checkpoint 在参数空间加权平均 | 五源 full-data base |
| Ensemble | 多个模型分别前向后融合 | 早期用过，最终避免大前向集成 |
| TTA | 同一样本多种变换推理后融合 | 多个实验验证，未成为最终核心 |
| EMA | 训练中维护参数滑动平均 | 基础训练稳定化 |
| MixUp | 混合两个样本与标签 | 基础正则化 |
| Label smoothing | 让监督标签不过度绝对 | 降低过拟合 |
| BF16 | 16 位浮点计算格式 | 训练与前向加速 |
| FP32 | 32 位浮点格式 | 优化器状态与高精度部分 |
| INT8 | 8 位整数存储 | 主干文件压缩 |
| Quantization | 用低比特表示权重/激活 | 满足 100 MB |
| Fold | 一组训练/验证划分 | Fold 0、Fold 1 |
| Ablation | 一次只改变一个因素的对照 | 判断模块真实贡献 |
| Incumbent | 默认可信预测 | V127/V24 保护路径 |
| Challenger | 候选替代预测 | Radar 结构解码结果 |
| Fallback | 条件不满足时回退 | V57 或 V24 |
| Rollback | 撤销已知风险改动 | 2025-05-31 四行规则 |
| Coverage protection | source 标签不覆盖时禁止适配器越权 | 恢复 decoded V24 |
| Raw accuracy | 每个 clip 独立 argmax 的准确率 | 判断视觉证据是否真的改善 |
| Decoded accuracy | 经过结构解码后的准确率 | 最终本地主要指标 |
| Public leaderboard | Kaggle 公开子集得分 | 用于有限线上证据 |
| Private leaderboard | 赛后隐藏子集得分 | 最终排名依据 |
| Transductive adaptation | 允许看到无标签测试输入并适配 | 测试伪标签训练小模块 |
| Data leakage | 不当使用目标标签或身份信息 | 通过人隔离和披露规避 |
| Byte-exact | 文件逐字节一致 | 最终两个 CSV 复现 |
| SHA-256 | 文件内容指纹 | 权重与提交完整性校验 |

## 12. 你应该形成的整体认识

### 12.1 早期提升来自表示学习

V1→V2：把输入处理正确；V2→V3：用真正的时空视觉模型。早期大幅涨分来自更好的原始表示。

### 12.2 中期提升来自训练系统与压缩

V24→V57：全量重训、参数汤、伪标签、logit residual 和 round distillation。重点是把复杂教师能力压进小模型。

### 12.3 后期提升来自条件化决策

V89→V127：多尺度、受保护 Adapter、同人跨环境适配、按监督可用性路由。重点不再是“统一模型对所有样本都更强”，而是“不同条件使用最可靠的专家”。

### 12.4 最终取舍来自泛化而非本地极值

V160/V166 提醒我们：结构规律很容易过拟合采集脚本。V164 用神经证据门控降低风险，而最终主提交仍选择更稳健的 V127。

### 12.5 最值得讲的研究结论

> 在小样本跨用户多模态任务中，继续扩大模型容量不一定改善未知人员泛化；更有效的路线是强共享表征、受保护的参数高效适配、按监督条件路由，以及让结构先验服从独立神经证据。
