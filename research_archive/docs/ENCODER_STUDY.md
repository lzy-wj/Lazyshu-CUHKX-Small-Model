# 编码器诊断与受控训练实验

日期：2026-09-07。用户同意检查是否编码不足，并测试容量、训练时长和分阶段训练。只使用 CNN / RNN / Transformer，不使用任何外部预训练模型或预训练特征，不自动提交 Kaggle。

## 1. 同一个最佳权重下的干净评估

逐个加载首轮 best.pt（EMA 权重），训练侧只评估该模型实际使用的训练片段，验证侧仍为完整 652 个片段。两侧均关闭数据增强、模态 dropout，并使用相同图像尺寸、采样策略、BF16 推理模式和 batch size。不是拿第 60 轮训练日志与某个早期最佳验证成绩直接相减。

| 模型 | 最佳 epoch | 干净训练准确率 | 完整跨用户验证准确率 |
| --- | --- | --- | --- |
| 骨架 | 12 | 94.69% | 46.47% |
| IMU | 12 | 89.07% | 20.55% |
| 雷达 | 32 | 50.46% | 12.88% |
| IR | 38 | 69.53% | 26.84% |
| Thermal | 18 | 62.65% | 28.53% |
| Depth_Color | 24 | 55.01% | 30.67% |
| 六路拼接 | 58 | 99.08% | 50.46% |
| 六路 Transformer | 28 | 97.27% | 47.55% |

训练侧是实际可用训练子集，单模态验证包含缺失输入，因此报告另含 available_accuracy 供核查；例如骨架有效验证为47.72%、IMU为20.90%，仍有很大的用户泛化差距。不能把覆盖率不同产生的差异全部解释为过拟合。

这些结果支持“存在明显泛化差距”，不支持“所有分支只需多训几轮”。视觉最佳 checkpoint 的训练拟合尚不高，但它们是在不同早期 epoch 选出的权重，不能据此直接证明容量或训练时长不足；由后续对照判断。

复测不是逐位确定性的承诺。首次 IR 复测有3个近决策边界样本翻转，诊断因此中止核查；重跑时明确记录概率差异和翻转样本，超过最大概率差0.02或1%样本翻转则报错。最终8个模型的准确率都与原记录一致，但 Transformer 有1个预测类别改变（未改变正确数），不是模型涨分。完整原始/复测统计在 `outputs/study_encoders/diagnosis/report.json`；最初运行的部分输出不当成最终诊断。

## 2. 五个有界实验

所有任务固定 Fold 0、seed 42、batch size 24、160px/16帧输入、原预处理及增强，学习率初值0.001。

| 名称 | 改动 | 主要对照 |
| --- | --- | --- |
| encoder_v1_depth_long_f0 | 深度仍用原网络，训练120轮 | 原60轮深度30.67% |
| encoder_v1_depth_wide_f0 | 深度CNN空间及时间宽度翻倍，仍60轮；1.38M→5.19M参数 | 原60轮深度30.67% |
| encoder_v1_staged_concat_f0 | 加载六个本折单模态编码器，重新初始化融合分类头，再联合训练60轮 | 原从头联合拼接50.46% |
| encoder_v1_concat_long_f0 | 原拼接模型从头训练120轮 | 原60轮拼接及分阶段拼接 |
| encoder_v1_staged_transformer_f0 | 加载相同六个单模态编码器，随机初始化Transformer/分类头，联合训练60轮 | 原从头联合Transformer47.55% |

长训练保留原60轮余弦学习率轨迹；第61～120轮固定为末端学习率5e-5，不让余弦函数再次升高学习率。CPU审计逐轮检查前60轮学习率值和原公式一致。相同配方不代表 CUDA 训练能逐位重现。

分阶段模型所有参数均继续更新，不冻结编码器，不复用单模态分类头、优化器状态或单模态类别先验。此处的“编码器预训练”仅指在同一 fold 的训练样本上完成监督学习，不是使用别人训练的模型。

分阶段训练额外使用了六个单模态的训练计算和验证 checkpoint 选择，所以并非与60轮直接联合训练等算力。增加120轮直接拼接控制“仅仅训练更久”的可能性，但也不能把它说成严格等计算量、等学习率经历的因果对照。

## 3. 初始化与隔离保护

- 通用 `--init` 仍不允许用于严格 scratch 模式；专用 `--encoder-sources` 必须恰好覆盖每个目标模态一次。
- 来源必须是项目内已完成的独立单模态 scratch checkpoint，无外部预训练、无初始化链，数据元信息哈希必须一致。
- 来源 fold 必须相同，训练索引必须精确匹配该模态可用的本折训练子集，且属于目标训练集；验证索引必须一致。
- 所有来源先完整核验，再原子式应用到模型，拒绝时不部分加载。仅加载 `encoders.<modality>.*`，张量名和形状严格匹配，不允许静默部分加载。
- 记录每个来源的 SHA256、划分哈希、epoch、训练样本数及加载张量数。预测只依赖目标模型自身的权重，不需要把六个来源模型放进推理包。
- 跨fold、外部预训练、验证样本混入、错误划分、数据哈希变化、结构不匹配、重复模态等均有拒绝测试。
- 自动全量重训入口拒绝直接重放分阶段配方，避免用Fold 0编码器假装全量阶段已被正确复现；需要另外明确对应的全数据编码器来源。

## 4. 运行与产物

```bash
conda run --no-capture-output -n Train python scripts/audit_encoder_study.py
bash scripts/run_encoder_diagnosis.sh 2
bash scripts/run_encoder_smoke.sh 7
bash scripts/launch_encoder_study.sh
```

GPU和tmux在当前受限环境中需要已获准的沙箱外执行。脚本只调度空闲的GPU 2、3、7，使用文件锁，不干扰其他任务。SwanLab继续记录到原私有项目，正式名称前缀 `encoder_v1_`。

- 配置：`configs/encoder_study.json`。
- 审计：`outputs/study_encoders/audit.json`。
- 干净诊断：`outputs/study_encoders/diagnosis/`。
- 动态状态：`outputs/study_encoders/report.json`。
- 模型及逐轮记录：`outputs/checkpoints/encoder_v1_*/`。
- 调度会话：`encoder_study`；日志 `outputs/logs/encoder_study.log`，退出码 `outputs/logs/encoder_study.exit`。

冒烟实验以 `encoder_smoke_` 命名，每次仅两个训练batch，不参与排名。正式任务启动不等于已经产生性能收益，不自动改推荐模型，不扩展到其他fold或提交。
