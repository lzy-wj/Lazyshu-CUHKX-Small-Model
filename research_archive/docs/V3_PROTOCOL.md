# 第三轮：尚未达到目标

用户要求约 95%；前两轮的 63.45% 加权用户隔离验证不等于目标完成，亦不是 Kaggle 测试分数。

## 诊断和实验

- 第二轮合并验证中，吃药召回率 11.1%、使用手机 20%、看文件 25%；大幅度动作相对较好。
- 对照实验固定为 16 帧、空间池化 2×2、MobileNetV3、三个视觉模态及骨架/IMU，比较启用与关闭 Temporal Shift。不是把不同训练预算的结果当成严格消融。
- Temporal Shift 只在残差分支内交换相邻帧的部分通道，保留原始 shortcut；不增加参数，旧 checkpoint 默认关闭，兼容第二轮预测。
- 审计原始 IMU 的相对时间和窗口统计，检查固定 64 点插值是否丢失运动信息；绝不加入绝对日期、用户 ID 或设备 MAC。
- 抽样审计发现多数片段每个 IMU 只有约 7–68 个点，原始采样约 10Hz；因此没有证据把主要问题归因于 64 点降采样。不盲目增加采样点数。
- 增加原始佩戴坐标 IMU 分支，与世界坐标 IMU 一起保留；比较全局统计和二段/四段统计编码，以保留动作先后关系。
- 新的 `imu_timed` 使用相对真实时间对齐各 IMU，保留佩戴坐标、世界坐标、重力方向、动态分量和片段时长；没有绝对日期和身份信息。
- `imu_relative` 改用胸部参考系的相对旋转矩阵、加速度和角速度，处理四元数符号连续性；胸部传感器缺失时关闭该分支。
- 增加 X3D-S 视频预训练对照，Kinetics-400 权重来自 PyTorchVideo 官方发布；去掉原分类头，保留小型 3D 视频编码器。使用 13 帧、160×160 输入，依赖固定在 `configs/video-requirements.txt` 并装入 `.tools/python`，不升级共享环境。
- 结构选择仍仅使用 Fold 0，固定候选后再检查 Fold 1。不将训练成绩、随机帧划分或反复调参的验证成绩称作测试准确率。

TSM 参考：`mit-han-lab/temporal-shift-module` 官方实现及 ICCV 2019 原论文。
现有比赛禁止 LLM 开发与外部预训练适用范围的合规风险不变；本轮仍属研究，不自动提交。
保存 `outputs/final_v2/`；第三轮只有复核出收益后才更新推荐产物。

## 融合选择

固定第二轮完整融合的内部权重与温度；仅在 Fold 0 上拟合新 X3D 温度，以及新模型和旧融合之间的一个混合比例（21 个候选点）。不重新搜索全部模型权重，也不根据 Fold 1 调整混合比例。入口 `scripts/calibrate_v3.py` 要求 Fold 0 正常结束，且拒绝覆盖已冻结配置。
新全量重训将总轮数、调度长度和 warmup 都按训练步数近似折算；前两轮已经训练好的最终模型不重训、不覆盖。

## 中途停止

`v3_shift_f0` 和 `v3_spatial_f0` 运行至少 32 轮后仍低于 55%，同期 X3D 超过 64%，因此主动停止较弱路线，将显卡转给独立用户复核。两项状态记为 pruned，而非正常完成；最佳权重与日志保留。
